# Journal Agent — панель здоровья

Версия приложения: 0.2.52.1. Desktop Commander: 0.2.52.

Минимальный HTTP-сервер на встроенных модулях Node.js, в том же контейнере,
что и агент. Без базы данных, сборки фронтенда и дополнительных npm-пакетов.
Umbrel app_proxy направляет запросы на порт 3000 с обычной авторизацией Umbrel.

## Что проверяется

- RPC: POST tools/call → настоящий https://mcp.desktopcommander.app/mcp →
  устройство из текущего device.json → read_file первой строки
  /journal/weekly-log/README.md → ответ. Проверяются ID ответа, отсутствие
  ошибки и подтверждение завершённого чтения; HTTP 200 или pending недостаточно.
- Journal: отдельное чтение каталога /journal и непустого файла канона.
- Версия берётся из package.json фактически запускаемого Desktop Commander.
- Uptime отсчитывается от запуска процесса агента, а не хоста или браузера.

Зелёный статус требует успешных RPC и Journal, живого процесса и результата
моложе 90 секунд. Ошибка новой проверки снимает зелёный сразу. Нет данных или
результат устарел — «Не подтверждено». Недоступна панель или остановлен агент —
«Нет соединения». Время выводится в Europe/Moscow.

При открытии панели, по кнопке и раз в минуту в видимой вкладке выполняется
один read_file. Опрос интерфейса каждые 5 секунд читает только локальный кэш.
Закрытая панель не запускает фоновые Remote MCP-вызовы. Одновременные проверки
объединяются. Таймаут 20 секунд, поздний ответ не заменяет результат таймаута.
Последняя успешная проверка хранится в памяти и сбрасывается при перезапуске.
Проверяется путь Remote MCP → агент → журнал, а не авторизация отдельного
ChatGPT-коннектора. Изменение протокола/формата ответа приводит к непройденной
проверке, а не к ложному зелёному статусу.

## Данные и установка

Авторизация остаётся в существующем томе rdc-home. Только Desktop Commander
обновляет её; панель читает актуальный access token и никогда не обновляет
refresh token. Токены, ответы инструментов и содержимое журнала не передаются
в браузер. Проверка ничего не записывает в /journal.

Существующее подключение папки /journal задаётся в Umbrel отдельно от
репозитория. Сохраните его и доступ к /radar при обновлении. Новый пустой
журнал не создаётся; без канона проверка будет неуспешной.

1. Опубликовать изменённую папку alex-remote-desktop-commander целиком
   в существующем umbrel-private-apps. Одного изменения версии недостаточно:
   нужны также каталог health и docker-compose.yml.
2. Обновить каталог приложений в Umbrel и применить Update для Journal Agent
   до 0.2.52.1. Это штатное обновление существующего приложения; не удалять
   приложение и том rdc-home. Простого Restart недостаточно.
3. Открыть Journal Agent, нажать «Проверить сейчас», дождаться результата.
   Если чтение /journal не подтверждено, проверить сохранённое подключение
   папки и наличие weekly-log/README.md.

Обновление перезапустит агента и временно прервёт Remote MCP. При остановке
обёртка завершает группу процессов агента; при его падении выходит с ошибкой,
чтобы существующая политика restart: on-failure могла перезапустить контейнер.
Для отката вернуть предыдущую папку приложения и применить её обычным способом,
сохраняя том авторизации и подключённые папки.

## Проверки разработки

Node.js 22, из каталога приложения:

```sh
node --test health/*.test.mjs
```

9 тестов покрывают недоказанный Online, успешную и просроченную проверку,
ошибки RPC/Journal, остановку процесса, одновременные вызовы, таймаут и поздний
ответ, ошибочные/незавершённые MCP-ответы, закрытый набор HTTP-маршрутов,
защиту POST от межсайтового вызова и завершение дочернего процесса.

Все 9 тестов также прошли на действующем Umbrel. Отдельно проверены
remoteProbe, journalProbe и полный
POST /api/check с реальным Remote MCP: HTTP 200, healthy, rpc=ok, journal=ok.
В браузере проверены отображение, кнопка и снятие зелёного при потере HTTP-связи.
Compose и manifest разобраны YAML-парсером; команда разрешает закреплённый
npm-бинарник на Umbrel.
